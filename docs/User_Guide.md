# WHEELTEC C50X 调试监视器使用手册

这份手册以**通过 ROS 控制小车走直线**为主线。当前有两条使用路径：

| 目标 | 主要页面 | 依赖的数据与车端节点 |
| --- | --- | --- |
| 用 IMU、里程计辅助直线前进 | **ROS** | 小车里程计、IMU、普通 PID 直行节点 |
| 用激光雷达建图，再进行雷达辅助直线前进 | **定位精度**，部分操作在 **ROS** | 雷达驱动、FAST-LIO、实时 `/Odometry`、`/active_imu`、雷达辅助直行节点 |

两条路径都通过 ROSbridge 向车端发送命令。下文的**停止**按钮是实际运动控制的一部分；实验前留出空旷区域，并保持可以随时停止小车。

## 1. 安装和启动上位机

在 Windows 上安装 Python 3.11 或更新版本及 `uv`，在仓库根目录执行：

```powershell
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.venv\Scripts\python.exe src\main.py
```

以后只需执行最后一行。主窗口顶部有 **汇总、编码器、IMU、ROS、ROS IMU、ROSBag、定位精度** 七个模块；本手册的两种直线实验主要使用 **ROS** 和 **定位精度**。其他模块见第 7 节。

## 2. 连接小车的 ROS

### 2.1 选择 IP 并连接

先看电脑连接的是哪一个网络，再到 **ROS** 页面填写主机地址，端口保持 `9090`，点击 **连接**：

| 电脑连接的网络 | ROS 主机 IP |
| --- | --- |
| 小车的 Wi-Fi | `192.168.1.100` |
| `RDRC_A10` | `192.168.1.14` |

程序当前可能预填 `192.168.0.14`；使用上述网络时请手动改成表中的地址。成功连接后，页面会显示连接和健康状态。**连接成功只证明 ROSbridge 通了**：还需勾选话题并点击 **应用订阅**，若车端正在发布消息，才能看到小车的实时数值和曲线。

**ROS、ROS IMU、ROSBag、定位精度**使用同一条 ROSbridge 连接。在一个页面断开，会影响其他页面。定位精度页的连接按钮提示“请在 ROS 页连接”，应回 ROS 页面操作。

### 2.2 确认本次实验的数据

在 **ROS 数据 topic 订阅** 中选择需要的话题，然后点击 **应用订阅**。可先用预设 **基础低带宽**（`/odom`、`/imu`）或 **定位**，再按实际发布的话题增减勾选。查看 **ROS 数据**区和 **速度监视**曲线是否持续更新；到 **ROS IMU** 页可比较 `/imu` 与 `/active_imu` 的数据。

FAST-LIO 里程计 topic 默认为 `/Odometry`。ROS 页与定位精度页的 topic 文本和勾选状态会同步，但改变勾选后仍须点击 **应用订阅**，实际订阅才会启停。定位页右上方出现 `/Odometry: 在线`、实时位姿不断变化，才能确认定位样本进入上位机。仅看到按钮“启动命令已发送”还不表示车端节点已经运行，应继续看节点状态标签。

### 2.3 车端准备

ROS 主机需要运行 `rosbridge_server`；节点启动、停止依赖车端的 `launch_manager`。冻结地图需要可写的 `/mapping/map_update_enable` 参数以及 `/Laser_map` 地图话题，通常还需要 `rosapi`。这几个服务不属于“连接”按钮自动启动的内容。如果状态显示**数据静默**，说明通道可能仍连着，但当前订阅的话题没有新消息。

## 3. 方案一：IMU＋里程计直线前进

这一方案使用 **ROS → PID 直行控制 /line_follow_control**。上位机启动普通 `pid_control.launch`，由车端控制节点执行直行控制；具体使用哪一路 IMU 与里程计，以车端 launch 配置为准。

1. 按第 2 节连接 ROS。选择 `/odom` 和实际使用的 IMU 话题（`/imu` 或 `/active_imu`），点击 **应用订阅**。确认数值或曲线持续更新。若车端普通 PID 节点使用的输入不同，应以车端配置为准，先确认对应话题正常发布。
2. 在 **PID 直行控制 /line_follow_control** 区点击 **启动 PID 节点**。等待“**PID 节点运行中**”的状态回报。若仍是“启动命令已发送”或“未运行”，不要开始运动。
3. 将 `linear.x` 设为一个小的目标速度；界面初始为 `0.2 m/s`。确认小车朝向和前方空间，再点击 **PID 前进**。
4. 观察实际/目标轮速、车体运动方向及 IMU、里程计数据。需要结束时点击 **PID 停止**，确认小车停稳，再点 **停止 PID 节点**。

**PID 后退**使用同一目标速度进行后退；初次测试应先在低速下核对方向。`/cmd_vel` 区的 **发送/停止** 是另一组速度命令，做 PID 直线实验时按上述 PID 控件操作，以免把两种命令混用。

## 4. 方案二：激光雷达建图与雷达辅助直线前进

这个方案有两个阶段：**先建图并获得 FAST-LIO 位姿，再用实时雷达里程计参与直线控制**。上位机可以启动节点、显示轨迹、冻结并保存地图；建图时需要让雷达观察到周围环境并随小车移动。软件没有单独的“自动走完建图路线”按钮。

### 4.1 启动雷达和 FAST-LIO

1. 按第 2 节连接 ROS，切换到 **定位精度** 页面。检查顶部 FAST-LIO 里程计 topic 为车端实际发布的名称，通常是 `/Odometry`。
2. 点击 **启动雷达节点**，等待状态显示“**雷达节点 运行中**”。该按钮向车端请求启动 `wheeltec_lidar.launch`；只看到“启动命令已发送”时继续等待状态更新。
3. 点击 **启动 FAST-LIO**，等待“**FAST-LIO 运行中**”。该按钮请求启动 `mapping_c16.launch`。如果节点本来已运行，不要重复启动，以页面状态为准。
4. 勾选 **FAST-LIO 里程计** 并点击 **应用订阅**。确认顶部显示 `/Odometry: 在线`，右侧实时位姿中的 `x/y/yaw` 更新，左侧开始画出轨迹。若没有轨迹，先排查 `/Odometry` 是否发布，再检查订阅；不要仅凭 ROSbridge“已连接”判断建图成功。

### 4.2 实际建图

1. 在车端雷达和 FAST-LIO 均运行、里程计持续更新后，让小车在待测试区域**缓慢移动**，使雷达扫过要使用的直线路段及周围环境。可使用现场已有的人工操控方式；若通过本软件控制移动，应有人观察小车并能够立即发送停止命令。
2. 回到 **定位精度** 页面，观察轨迹随着移动延长。建图更新期间，地图点云不一定直接显示在本页：本页的灰色**冻结点云地图**是冻结后从 `/Laser_map` 获取的一次快照。
3. 确认已覆盖需要的区域后，核对 **建图参数**（默认 `/mapping/map_update_enable`）和 **地图 topic**（默认 `/Laser_map`）。点击 **冻结建图**。软件先把建图更新参数设为 `false`，再获取一次地图。等待状态出现“**建图已冻结，已获取 N 个地图点**”，左侧应叠加灰色地图点和轨迹。
4. 点击 **保存地图与轨迹数据**，选择 ZIP 路径。这个按钮要求**冻结地图已成功取得**且已有轨迹样本；保存完成后查看“地图 N 点、轨迹 N 点”的提示。`本地地图路径` 留空时从 `/Laser_map` 获取；只有明确要使用已有本地地图文件时才填写该路径。
5. 需要继续更新地图时，点击同一位置的 **恢复建图**。恢复后旧的冻结地图覆盖层会从界面清除；要保存此前快照，应在恢复前完成导出。

**冻结成功但地图获取失败**时，建图更新已经停下，界面却没有可导出的地图。检查 `/Laser_map` 是否发布 `sensor_msgs/PointCloud2`、主机地址、建图参数及 `rosapi`；需要继续采图时点 **恢复建图**，解决问题后再冻结。导出的 ZIP 是地图与轨迹的数据包，**雷达辅助直行节点使用的是实时里程计，不会自动读取该 ZIP**。

### 4.3 用雷达里程计走直线

1. 保持雷达节点和 FAST-LIO 运行，确认 `/Odometry: 在线` 且实时位姿继续更新。如果冻结后定位数据不再更新，应先 **恢复建图** 并重新确认数据。雷达辅助控制还使用 `/active_imu`；可在 **ROS IMU** 页检查它是否有新数据。
2. 在 **定位精度** 页点击 **设置当前为起点**，让本次直线轨迹和误差统计从当前位置开始。需要保存测试数据时点击 **开始定位记录**。
3. 在 **雷达直线校准** 区点击 **启动校准节点**。上位机会请求车端运行 `pid_control_lidar_assisted.launch`，并传入 `/active_imu` 与当前 FAST-LIO 里程计 topic。等待状态显示“**校准节点运行中**”；只有车端状态确认运行后，**前进/后退**按钮才会启用。
4. 设定小的**目标速度**（初始 `0.2 m/s`），确认直线方向和通道无障碍后点击 **前进**。观察轨迹、实时位姿、横向误差和车体运动。需要结束时先点击 **停止**，待小车停稳后点击 **停止校准节点**。
5. 点击 **停止并保存 CSV**，选择定位记录路径；可用 **生成测试摘要**另存 Markdown 报告。需要保存地图快照时按第 4.2 节在冻结状态下导出 ZIP。

普通 PID 直行节点和雷达直线校准节点共用车端的 `pid_control` 标识，应先停止当前节点再切换方案。地图点云是否已经保存，不影响控制器对实时 `/Odometry` 的需求。

## 5. 如何记录一次直线实验

只需看轨迹时，用 **定位精度 → 开始定位记录**，结束后保存 CSV，并可生成测试摘要。若要同时保存 IMU、里程计、编码器等来源，使用 **汇总** 页面：

1. 选择保存目录，填写备注，并把**轨迹主话题**设为本次使用的 `/Odometry` 或 `/odom`。
2. 在**可记录数据源**中只勾选本次确实在发布的来源。普通直行可选 `/odom` 与 IMU；雷达方案可选 `/Odometry`、`/active_imu` 等。当前界面初始化时数据源均未勾选。
3. 点击 **检查可记录数据源**。离线或错误的已勾选来源会阻止开始；修复连接或取消该来源后重试。
4. 点击 **全部开始记录**，实验结束后点击 **全部停止记录**，等待 CSV、对齐文件和 ZIP 打包完成，再点 **打开目录** 检查文件。

如需车端原始雷达和 ROS 数据，可在 **ROSBag** 页面选择含 `/point_cloud_filtered`、`/Laser_map`、`/Odometry` 等话题的录制模式，或按需自定义；开始和停止车端 rosbag 后，选中 session 点击 **同步到 Windows**。**车端录制不等于已复制到电脑**。汇总页的 **同步车端 rosbag 录制** 可联动开始和停止；大型 `.bag` 文件不自动装入汇总 ZIP。

汇总会话通常包含 `session.json`、所选来源的 CSV、`aligned/` 对齐文件、`manifest.json` 和同名 ZIP。具体文件取决于选择的数据源和实际收到的消息。跨设备对齐还受时钟、网络延迟和消息频率影响，分析时先核对行数与 `session.json` 中的检查结果。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| ROS 连不上 | 核对电脑连接的是小车 Wi-Fi 还是 `RDRC_A10`，按第 2.1 节填写 IP；确认端口 `9090` 和车端 ROSbridge。 |
| 已连接但没有小车数据 | 确认话题在车端发布，勾选后点击 **应用订阅**；查看是否显示“数据静默”。 |
| PID 启动后小车不走 | 查看节点状态是否为“PID 节点运行中”、目标速度是否大于零、`/odom` 与 IMU 是否有数据；先确认停止命令可用。 |
| 雷达节点运行但没有轨迹 | 核对 FAST-LIO 也在运行，`/Odometry` 名称正确，且已勾选并应用 FAST-LIO 里程计订阅。 |
| 无法冻结或取到地图 | 核对 `/mapping/map_update_enable`、`rosapi`、`/Laser_map` 的消息类型及是否持续发布；若冻结后取图失败，先恢复建图再排查。 |
| 雷达直线校准的运动按钮不可用 | 等待 `/launch_manager/status` 确认校准节点运行；检查 `/active_imu` 和实时 FAST-LIO 里程计。 |
| 找不到保存的地图 | 地图与轨迹由 **保存地图与轨迹数据** 导出 ZIP；仅点击 **冻结建图** 不会弹出最终保存文件对话框。 |

## 7. 其他模块速查

- **编码器**：通过调试 UART1（默认 115200 bps）看电机曲线、发送 PID 与速度参数、记录和回放 CSV。接线及帧格式见[调试串口协议](Debug_UART_Protocol.md)。
- **IMU**：连接 A/B 两台串口 IMU，查看加速度、角速度和姿态，可单独记录。
- **ROS IMU**：查看 `/imu` 与 `/active_imu` 的实时数值与曲线，支持显示原始数据和平滑曲线。
- **ROSBag**：管理车端 rosbag 的开始、停止、列表、详情、同步及清理；删除前检查 session 和同步结果。
- **汇总**：同步记录多种来源并生成会话目录、对齐 CSV 和 ZIP。

常用默认值定义在 [`src/app_config.py`](../src/app_config.py)。ROSbridge 主机、地图话题等可通过界面输入或启动前的环境变量调整；具体以本次连接的小车网络和实际发布话题为准。
